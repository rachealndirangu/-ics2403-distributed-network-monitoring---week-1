## Cross-cutting lessons
1. **Measure what you think you measure.** Weeks 6, 8, 9 and 10 each contained an experiment that "worked" for the wrong reason (a hidden timeout, a double-counted cost, an overwrite masking a lost write, a missing control). Each was found by asking *"what else could produce this number?"* and fixed by adding a control or a stricter check.
2. **The same mistake twice.** The negative message count (week 4, week 12) came from the same cause — a before/after snapshot taken over different node sets. The week-4 lesson was in the log and still repeated; the fix this time was to put the rule in the code comment next to the snapshot.
3. **Failure experiments need a no-failure control and a "since observed" clock** (weeks 10, 12).
4. **Caches, retries and garbage collectors are hidden recovery mechanisms** — they decide how long recovery takes (week 10: a 60 s name TTL), whether it is correct (week 9: anti-entropy undoing a delete; week 12: a GC deleting live chunks) and whether a result is real (week 6).
5. **Negative and mixed results are kept**: the 2-process slow-down (week 2), the tiered design being slightly worse on loopback (week 3), the integrated model *not* winning when every core is priced (week 8), the proposed system being ≈ 2.8× slower than the baseline on an unconstrained link and collapsing under a 256 MB cap (week 12).
